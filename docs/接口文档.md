# OS Memory 接口文档（阶段 1 + 修复 + 阶段 2 + 阶段 3）

> 对齐 PPT 第 14 页：`memo_collect / memo_update` 与 `get_memo / auto_recommand`。
> 阶段 1/2 以 Repository 实现进程内接口；阶段 3 已由三个 vibe 应用通过 `MemoryApiClient` 实际调用；阶段 4 升级为 Binder/AIDL 跨进程形态。
> 阶段 2 补充：`get_memo` 增加 LLM 语义重排；新增 `memo_update`（先画像后改）；引入 Local/Cloud 双树与单向同步。

## 1. 应用接入（注册）

```
registerApp(appId: String, appName: String, scope: Scope)
scope ∈ {WRITE(只存), READ_WRITE(读写)}   // WRITE: 只允许 memo_collect；READ_WRITE: 另可用 get_memo
```

记忆安全原则（PPT 第 10 页）：应用必须先登记，读取受 scope 约束；敏感记忆（policyLevel=2）默认不向普通应用输出。

## 2. 写入记忆（memo_collect）

```
collect(appId, content, source): CollectResult
```

- 行为：净化 → 安全门控 → LLM 结构化抽取 → 去重 → 入库；全程留日志（COLLECT + INFER）
- 返回：`CollectResult.Success(item)` / `CollectResult.Duplicate(existing)` / `CollectResult.Rejected(reason)`
- 重复判定：归一化文本相同且同源 24h 内 → Duplicate

```
update(appId, memoId, newContent): CollectResult   // 阶段 2 提供：先画像后更新的语义化"修改"
```

```
delete(appId, memoId): DeleteResult                // 阶段 3：仅允许删除本应用创建的本地记忆
```

## 3. 读取记忆（get_memo，阶段 2：语义检索）

```
getMemo(appId, query, limit, policyMax, semantic): List<MemoryItem>
// semantic=true 时：关键词召回 → LLM 语义重排（离线/模型失败自动降级为关键词顺序并留痕）
```

- 关键词召回 + 权限过滤（policyLevel ≤ 应用权限）+ 命中自增 reuseCount + RETRIEVE 日志
- **语义重排（阶段 2）**：`core/retrieval/SemanticReranker` 让模型按相关性排序候选 memoId；
  重排状态（ai / 降级 + 原因）写入 RETRIEVE 日志 extra
- 阶段 4：读取前安全弹窗（用户确认后放行）

```
autoRecommend(appId, scene, limit): List<MemoryItem>   // 阶段 3 已落地：编译近期有效 Local Tree 上下文
```

- `autoRecommend` 仅返回 `policyLevel<=1` 且未过期的本地记忆，并写 RETRIEVE 日志；
  文件分类器再用统一 ModelProvider 根据 title/tags/content 摘要生成开放类别。

## 4. 画像（阶段 2 提供）

```
buildProfile(owner): ProfileSummary
// 三板块：用户画像 / 风格偏好 / 工作项目 + 遴选标签
// LLM 从本地树聚合生成；离线/失败统计降级（最高频标签），降级原因展示 + 留 INFER/RETRIEVE 日志
```

## 4.1 双树与单向同步（阶段 1 修复，对应 PPT Network Gateway / Pull）

- **Local Tree**：本地结构化记忆库（source of truth，离线可用，本地优先）
- **Cloud Tree**：云端企业/个人库（独立 `osmemory_cloud.db`，单向镜像）
- **Network Gateway**：`syncNow()` 在线时把"允许上云且非敏感（policyLevel<2 且 cloudEligible）"的记忆推送到云端；
  敏感/保密记忆永不外发（内网保密记忆隔离）；**本地树不读回云端内容**
- **离线路由**：Cloud Tree 不可达（UI 状态徽标提示），本地树独立可用

## 5. 阶段 3 Kotlin 调用入口

```kotlin
val client = MemoryApiService.client(context, Phase3App.CHAT)

client.memoCollect(content)
client.memoUpdate(memoId, content)
client.memoDelete(memoId)
client.getMemo(query, limit = 5, semantic = true)
client.autoRecommend(scene, limit = 60)
```

- `Phase3App.NOTES` 固定 `WRITE`；`CHAT`、`CLASSIFIER` 固定 `READ_WRITE`。
- 结果使用 `MemoCollectResult / MemoUpdateResult / MemoDeleteResult` 密封类型，调用方必须区分
  Success、Duplicate、Rejected、NotFound、Forbidden。
- 返回 `MemoryMemo` DTO，不向应用暴露 Room Entity；当前是同进程实现，阶段 4 保持语义换 IPC。
- 完整说明见 `docs/阶段3系统API与三应用说明.md`。

## 6. 日志（全链路可审计）

- COLLECT：记忆传入（时间/来源/内容摘要/标签/动作）
- RETRIEVE：记忆被应用调用（时间/应用/查询/命中数）
- INFER：模型推理场景（抽取/画像/整合，记录输入输出摘要）
