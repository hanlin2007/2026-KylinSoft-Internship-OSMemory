# OS Memory 开发路线图

本文区分当前仓库已经实现的原型能力与后续规划，避免把设计方向误解为现有功能。项目当前仍是单 APK、单进程的 Android 研究与演示原型。

## 已完成的原型能力

- Room 驱动的 Local Tree、独立 Cloud Tree 演示库和审计日志。
- 记忆净化、安全门控、模型结构化抽取、24 小时同源去重和降级入库。
- 关键词召回、可选模型语义重排、画像生成与调用诊断。
- Local → Cloud 单向同步，以及敏感/主动保密记忆不迁移的隔离策略。
- 在线 OpenAI 兼容模型与离线 llama.cpp + Qwen GGUF 动态路由。
- 备忘录、ChatBot、文件分类管理器三个同进程示例入口。
- 自包含 HTML 审计快照导出。

## 近期演进方向

- 完善 AutoDream 后台整合，包括合并、冲突识别、遗忘与降权策略。
- 建立更系统的图关系和向量检索能力，并补充可解释的召回评估。
- 扩大端侧模型支持范围，包括更多业务链路和 `arm64-v8a` 设备。
- 补齐数据库迁移、恢复、压力测试和端到端自动化测试。
- 继续完善用户授权、敏感操作确认和安全审计体验。

## 系统化方向

- 通过 Binder/AIDL、ContentProvider 或稳定协议提供真正的跨进程服务。
- 基于调用 UID、签名证书和用户授权完成应用身份校验与权限隔离。
- 引入硬件级密钥保护、加密数据库、多用户隔离和更严格的数据治理。
- 将 Cloud Tree 演进为远程服务，支持多设备同步、版本协商与冲突解决。
- 探索 MCP、Hook、Skills 和插件化机制，让不同 AI 应用以统一方式使用系统记忆。

上述方向均为规划，不代表当前仓库已具备。现有接口边界见 [对外接口文档](对外接口文档.md)，内部实现见 [架构设计说明](架构设计说明.md)，端侧范围见 [端侧模型说明](端侧模型说明.md)。
