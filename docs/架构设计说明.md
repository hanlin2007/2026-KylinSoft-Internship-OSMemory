# OS Memory 架构设计说明（阶段 1 + 修复 + 阶段 2 + 阶段 3）

> 对应 PPT 第 8/10/14 页的概念落地。本工程以"Android 原生应用形态"模拟 OS 用户态系统服务：
> 单 `:app` 模块，包结构即分层，后续阶段可逐步升级为 Binder/AIDL 跨进程服务。

## 1. 模块架构

```
┌────────────────────────────────────────────────────────┐
│ UI 层 (ui/)  控制台：记忆库(双树)/画像/调用日志/模型设置  │
│  - MemoryListFragment  Local/Cloud 树切换 + 语义检索     │
│  - ProfileFragment      画像三板块 + 遴选标签             │
│  - LogFragment          日志四板块(+安全敏感) + extra 展开          │
│  - ModelSettingsFragment base/model/key + 测试连接       │
├────────────────────────────────────────────────────────┤
│ 门面 (data/MemoryRepository)                            │
├───────────────────────┬────────────────────────────────┤
│ 核心服务 (core/)       │ 数据层                          │
│ MemoryPipeline        │ 本地树 OSMemoryDatabase          │
│ SecurityGate          │   memory_items (+云同步字段)     │
│ MemoryRetriever       │   memory_logs / registered_apps  │
│ SemanticReranker      │ 云端树 CloudTreeDatabase         │
│ ProfileBuilder        │   cloud_memory_items (独立db)    │

├───────────────────────┴────────────────────────────────┤

```

## 1.1 本地树 ↔ 云端树（阶段 1 修复，对应 PPT 第 14 页 Network Gateway / Pull）

```
                    在线/离线路由
  本地树(Local)  ────────►  NetworkMonitor(StateFlow)  ────────►  UI 状态条
   source of truth         (ConnectivityManager)
       │                                                       
       │ 单向拉取/同步 (云端可"拉取"本地)      │ 本地不能 pull 云端
       ▼                                  ▼
  TreeSyncManager  ──在线──►  CloudTreeDatabase (osmemory_cloud.db)
   (Network Gateway)         内网企业/政企云端库（只读展示 + 单向写入）
       │
       ├── 每次联网自动拉取：待同步记忆（联动「保密不迁移云端」标签）
       ├── 敏感判断与本地一致：来源两分（本地同步保留原值 / 云端创建按内容判断）
       ├── 云端 FAB：云端创建记忆（SecurityGate + LLM 取并集）
       └── 断网锁定：白色虚化遮罩 + 中央锁（内容不可查看）
```

- **Local Tree**：`memory_items`（source of truth，本地优先、离线可用）。新增 `cloudEligible`（是否允许上云）、`syncState`（0 仅本地/1 待同步/2 已同步/3 同步失败）、`syncedAt`。
- **Cloud Tree**：`cloud_memory_items`，独立 `.db` 文件 `osmemory_cloud.db` 模拟**内网企业/政企云端库**；仅由 TreeSyncManager 从本地树拉取上来（云端可"拉取"本地），**本地树从不从云端读回**（内网保密记忆隔离）。**敏感判断与本地一致**：来源两分——本地同步保留原判断（`policyLevel` 原值带入），云端创建按 `SecurityGate` + LLM 取并集判断（`origin` 计算属性：LOCAL_SYNC / CLOUD_CREATE）。
- **Network Gateway**：`TreeSyncManager.sync()`（手动同步）/ `autoIntegrateIfNeeded()`（**每次联网自动拉取**，联动「保密不迁移云端」标签）/ `addToCloud()`（云端 FAB 添加）三条写入路径；离线时返回"Cloud Tree 不可达"，本地树独立可用。
- **断网锁定**：`MemoryListFragment` 云端树展示**白色虚化遮罩 + 中央锁**（"当前为离线状态，云端树无法查看"），内容不可查看、不可离线、不可脱离。
- **降级可观测**：`ModelDiagnostics` 记录每次模型调用成败与原因；流水线把 `degradeReason`（网络/HTTP 状态码/解析失败/超时）写入日志 extra；日志条目点击展开可见。

## 1.2 阶段 3 多应用生态与系统 API

阶段 3 仍保持单 `:app` APK：记事本、记忆问答、文件分类器分别是独立 Launcher Activity，
通过 `phase3/api/MemoryApiService` 直接调用同进程 `MemoryService`。这既能在桌面独立演示三个
应用入口，又不会提前侵入阶段 4 的 Binder/AIDL 范围。

```text
NotesActivity(WRITE) ─────── memo_collect/update/delete ─┐
ChatActivity(READ_WRITE) ─── get_memo + memo_collect ────┼─► MemoryApiClient ─► Local Tree
ClassifierActivity(READ_WRITE) ─ auto_recommend ─────────┘        │
                                                                 └─► COLLECT/RETRIEVE/INFER 审计
```

- 应用身份与 `source` 由门面绑定，UI 不能伪造；首次调用自动幂等登记。
- 普通应用读取权限固定为 `policyLevel <= 1`，敏感记忆不进入问答上下文或分类扫描。
- 三应用不直接依赖 Cloud Tree、NetworkMonitor、TreeSyncManager 或 DAO；分类扫描只读取本地树。
- `MemoryMemo` DTO 与 Room Entity 解耦，阶段 4 可保持业务签名并替换传输层。

## 2. 数据模型（对应 PPT 第 9 页 Memory Item Card）

原子记忆卡 `memory_items`：

| 字段 | PPT 概念 | 说明 |
|---|---|---|
| memoId | — | 对外稳定标识（`MEMO-时间戳-随机`） |
| content | 内容 Content | 可解释自然语言，已净化 |
| title | — | LLM 抽取的一句话标题 |
| category | 封闭分类 | 画像/日程/项目/偏好/任务/关系/地点设备/其他 |
| tags | — | LLM 遴选标签，逗号分隔 |
| source / appId | 来源 Source | 来源应用与场景（控制台/记事本/对话/文件） |
| policyLevel | 权限 Policy | 0=公开 1=普通 2=敏感（安全门控输出依据） |
| createdAt/updatedAt/expiresAt | 时间 Time | 生成/更新/过期（毫秒时间戳） |
| confidence | 质量 Quality | LLM 置信度 0~1 |
| conflictState | 质量 | 0=无冲突 1=疑似冲突 2=已整合（AutoDream 阶段使用） |
| reuseCount | 质量 | 复用频率（检索命中自增） |
| evidenceRaw | 证据 Evidence | 原始片段（保留可追溯） |
| links | 连接 Links | 关联记忆/实体 JSON（阶段 2 图谱使用） |

记忆调用日志 `memory_logs`（对应 PPT 第 9 页与开发方案"日志板块"）：
`logType ∈ {COLLECT 传入, RETRIEVE 检索, INFER 推理, SECURITY 安全敏感}`，格式化字段：时间/来源/内容摘要/标签/动作/附加 JSON。
「安全敏感」板块只展示标记"敏感"的内容：敏感记忆的入库/修改/检索命中/云端保守策略等全部留痕。

## 3. 记忆处理流水线（对应 PPT 第 14 页 Memory Collection → Processing → Store）

```
raw_memo ──► MemoryPipeline.process()
 ① sanitize       trim / 长度校验（2~5000 字符）
 ② securityGate   敏感词栅栏命中 → policyLevel=2；LLM 敏感分类增强（失败不阻断）
 ③ extract        LLM 结构化抽取 {title, category, tags, entities, confidence}
                  └─ 网络失败降级：原文入库 + 置信度 0.3 + 日志标注"降级"
 ④ dedup          归一化文本 + 24h 同源重复 → 拒绝并记日志（reuseCount 场景）
 ⑤ store          入库 + COLLECT 日志 + INFER 日志（记录抽取过程）
```

设计要点：
- **安全门控前置**：敏感记忆在入库即打标，后续所有读取路径按 policyLevel 过滤（阶段 2 完整权限过滤，阶段 4 安全弹窗）。
- **降级优先**：任何模型调用失败都不阻断核心链路（收集/存储是硬能力，AI 增强是软能力）。
- **全链路留痕**：每条记忆的传入与推理过程都有日志，检索/画像/整合分别留日志——演示"可解释、可审计"。

## 4. 模型双通道设计

接口：`suspend fun complete(system: String, user: String, temperature: Double): String`

网关语义：联网/政企内网 = **"云端状态"**（走云端大模型，算力更强）；离线/本地网关 = 手机端部署的本地小模型。
两者共享 `ModelProvider` 业务接口：云端使用 OpenAI 兼容 HTTP 端点，端侧使用 llama.cpp JNI 加载固定 GGUF；每次 `complete()` 都重新判网。

| 通道 | 实现 | 路由 | 状态 |
|---|---|---|---|
| CloudModelProvider | OpenAI 兼容 `POST {base}/chat/completions`；端点自动适配 `/v1` 变体；30s 超时；健壮 JSON 提取 | 联网/内网（云端状态） | ✅ 启用（默认） |
| LocalModelProvider | llama.cpp Android/JNI；Qwen2.5-0.5B-Instruct Q4_K_M；固定大小与 SHA-256 校验 | 离线/本地网关 | ✅ 阶段 4 已启用（x86_64 模拟器） |

**本地小模型落地结论**：本轮已用官方 llama.cpp Android/JNI 跑通约 6.3 亿参数的
Qwen2.5-0.5B-Instruct Q4_K_M；GGUF 在首次本地测试时下载到应用私有目录，不进入 APK。
本轮 ABI 按验收范围仅构建 x86_64 Android Emulator。

配置（`core/ModelConfig.kt`）：默认值 = PPT 调研选定的云端模型（BaseURL/Model/Key），
可被 SharedPreferences 覆盖（阶段 2 提供设置页）。
