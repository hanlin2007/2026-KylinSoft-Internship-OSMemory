# OS Memory 对外接口文档

本文面向准备把业务功能接入 OS Memory 的 Android 开发者。这里描述的是**当前仓库已经可以调用的接口**：调用方式、权限、返回结果、错误与接入边界都以现有同进程 Kotlin API 为准。

> 如果你只想先理解系统整体设计，请先读 [架构设计说明](架构设计说明.md)。如果你还没有运行项目，请回到根目录 [`README.md`](../README.md) 完成 Android Studio 环境配置。

## 1. 一分钟了解当前 API

| 问题 | 当前答案 |
|---|---|
| 对外入口是什么？ | 同 APK、同进程的 Kotlin `MemoryApiClient` |
| 有哪些方法？ | `register`、`memoCollect`、`memoUpdate`、`memoDelete`、`getMemo`、`autoRecommend`、`recordInference` |
| 业务应用需要提供什么？ | 固定应用身份、自然语言内容 / 查询、业务对象与 `memoId` 的映射，以及用户是否允许建立记忆关联 |
| 什么由 OS Memory 负责？ | `appId` / `source`、标题、分类、标签、敏感等级、时间戳、模型路由与审计 |
| 敏感记忆能读吗？ | 普通业务应用不能读取 `policyLevel=2` 的敏感记忆 |
| API 会访问 Cloud Tree 吗？ | 不会；当前 `MemoryApiClient` 的业务接口只访问 Local Tree |
| 独立第三方 APK 能直接调用吗？ | 不能；当前尚未实现 Binder/AIDL、ContentProvider 或 HTTP API |

## 2. “对外接口”目前意味着什么

当前调用链是：

```text
业务 Activity / Fragment
        │
        ▼
MemoryApiService.client(context, Phase3App)
        │
        ▼
MemoryApiClient
        │
        ▼
MemoryRepository / MemoryPipeline / Room / ModelProvider
```

因此，“对外”是相对于 OS Memory 内部实现而言，并不代表它已经成为 Android 跨进程服务。现阶段接入方仍需要与 OS Memory 一起编译进 `com.example.osmemory` 这个 APK。

当前**不是**：

- Binder/AIDL 系统服务；
- exported Android Service；
- ContentProvider；
- REST / HTTP / WebSocket 服务；
- 可直接从另一个已安装 APK 调用的 SDK。

现有 DTO 和方法语义可以作为未来 IPC 层的基础，但不要把下面的 Kotlin 示例复制到独立 APK 后期待直接生效。

## 3. 获取客户端

推荐入口位于：

```kotlin
package com.example.osmemory.phase3.api
```

创建客户端：

```kotlin
import com.example.osmemory.phase3.api.MemoryApiService
import com.example.osmemory.phase3.api.Phase3App

val memoryClient = MemoryApiService.client(
    context = applicationContext,
    app = Phase3App.CHAT
)
```

客户端使用 `applicationContext`，不会持有 Activity。公开接口均为 `suspend` 函数，建议从 `lifecycleScope`、`viewModelScope` 或其他受控协程作用域调用。

## 4. 应用身份与 scope

当前应用身份不是运行时任意注册的字符串，而是由 `Phase3App` 固定绑定：

| `Phase3App` | 显示入口 | `appId` | `source` | `scope` |
|---|---|---|---|---|
| `NOTES` | 备忘录 | `app_notes` | `notes` | `WRITE` |
| `CHAT` | ChatBot | `app_chat` | `chat` | `READ_WRITE` |
| `CLASSIFIER` | 文件分类管理器 | `app_files` | `files` | `READ_WRITE` |

这意味着调用 UI 不能在每次请求中伪造 `appId` 或 `source`。如果要增加新的逻辑应用，需要先在 `MemoryApiContract.kt` 中加入经过审查的 `Phase3App` 枚举值，并重新编译 APK。

### 4.1 scope 能做什么

```kotlin
enum class MemoryScope {
    WRITE,
    READ_WRITE
}
```

| 能力 | `WRITE` | `READ_WRITE` |
|---|---:|---:|
| `register` | ✅ | ✅ |
| `memoCollect` | ✅ | ✅ |
| 修改自己创建的记忆 | ✅ | ✅ |
| 删除自己创建的记忆 | ✅ | ✅ |
| `getMemo` | ❌ | ✅ |
| `autoRecommend` | ❌ | ✅ |
| `recordInference` | ✅ | ✅ |

`WRITE` 应用调用读取接口会抛出 `MemoryApiAccessException`。无论 scope 是什么，更新和删除都只能处理当前 `appId` 自己创建的记忆。

## 5. 注册应用：`register`

```kotlin
suspend fun register()
```

```kotlin
memoryClient.register()
```

注册会把固定的 `appId`、显示名称和 scope 幂等写入 `registered_apps`。重复调用不会创建多份记录。

通常不需要在每次使用前显式调用：其他 API 会在首次调用时自动完成注册。`register()` 本身没有返回值，数据库等未预期基础设施错误仍可能作为异常抛出。

## 6. 通用 DTO：`MemoryMemo`

成功写入、重复命中和读取结果使用与 Room Entity 解耦的 DTO：

```kotlin
data class MemoryMemo(
    val memoId: String,
    val content: String,
    val title: String,
    val category: String,
    val tags: List<String>,
    val source: String,
    val appId: String,
    val policyLevel: Int,
    val createdAt: Long,
    val updatedAt: Long,
    val confidence: Float
)
```

| 字段 | 含义 |
|---|---|
| `memoId` | 系统生成的稳定记忆 ID；后续更新、删除和业务映射都依赖它 |
| `content` | 净化后的正文 |
| `title` | 模型抽取或降级生成的短标题 |
| `category` | 结构化记忆类别 |
| `tags` | 标签列表 |
| `source` | 与应用身份绑定的来源，例如 `chat` |
| `appId` | 创建这条记忆的应用身份 |
| `policyLevel` | `1` 普通、`2` 敏感；普通业务应用最高读取到 `1` |
| `createdAt` | 创建时间，Unix epoch milliseconds |
| `updatedAt` | 最近更新时间，Unix epoch milliseconds |
| `confidence` | 结构化结果置信度；降级时使用降级值 |

这是当前进程内的 Kotlin 对象，不是网络传输 JSON。

## 7. 写入记忆：`memoCollect`

### 7.1 签名

```kotlin
suspend fun memoCollect(
    content: String
): MemoCollectResult
```

调用方只需要提供自然语言 `content`。系统负责应用身份、结构化字段、敏感判断、时间和审计。

```kotlin
val result = memoryClient.memoCollect(
    "我计划周六上午复习 Android JNI，并整理端侧模型部署笔记。"
)
```

输入 trim 后不能为空，最大长度为 5000 个字符。更推荐一次提交一条相对独立、可以脱离原上下文理解的事实、偏好、计划或事件，而不是整段聊天历史。

### 7.2 处理流程

```text
trim / 长度校验
→ 确定性安全规则
→ 在线云模型或离线端侧模型结构化抽取
→ 安全规则与模型敏感判断取并集
→ 24 小时同 source、同归一化正文去重
→ Local Tree 入库
→ COLLECT / INFER；敏感时另写 SECURITY 日志
```

模型失败不会直接导致记忆丢失：流水线会使用确定性降级结构继续入库，并通过结果与日志明确标记降级。

### 7.3 返回结果

```kotlin
sealed interface MemoCollectResult {
    data class Success(
        val memory: MemoryMemo,
        val degraded: Boolean
    ) : MemoCollectResult

    data class Duplicate(
        val memory: MemoryMemo
    ) : MemoCollectResult

    data class Rejected(
        val reason: String
    ) : MemoCollectResult
}
```

- `Success`：创建成功；`degraded=true` 表示结构化过程使用了降级逻辑。
- `Duplicate`：24 小时内命中同 `source`、同归一化正文，不重复创建。
- `Rejected`：输入为空或超过 5000 个字符。

处理示例：

```kotlin
when (val result = memoryClient.memoCollect(userText)) {
    is MemoCollectResult.Success -> {
        saveMapping(localRecordId, result.memory.memoId)
        showMessage(if (result.degraded) "已降级保存" else "已写入记忆")
    }

    is MemoCollectResult.Duplicate -> {
        showExistingMemory(result.memory.memoId)
    }

    is MemoCollectResult.Rejected -> {
        showMessage("未保存：${result.reason}")
    }
}
```

> 对业务应用来说，`memoId` 是最重要的关联字段。保存成功后应建立“业务对象 → `memoId`”映射，后续更新和删除才能保持一致。

## 8. 更新记忆：`memoUpdate`

```kotlin
suspend fun memoUpdate(
    memoId: String,
    content: String,
    forceSecret: Boolean? = null
): MemoUpdateResult
```

参数：

| 参数 | 说明 |
|---|---|
| `memoId` | 需要更新的系统记忆 ID |
| `content` | 新正文；trim 后不能为空，最多 5000 个字符 |
| `forceSecret` | `true` 强制不允许同步；`false` 对非敏感内容允许同步；`null` 沿用原同步偏好 |

`forceSecret` 只控制是否允许同步到 Cloud Tree，不能用来主动降低敏感等级。只要安全规则或模型把内容识别为敏感，系统都会强制使用敏感策略。

更新保留 `memoId` 与 `createdAt`，重新执行安全判断和结构化抽取，刷新 `updatedAt` 并写入审计日志。

```kotlin
sealed interface MemoUpdateResult {
    data class Success(
        val memory: MemoryMemo,
        val degraded: Boolean
    ) : MemoUpdateResult

    data class NotFound(val memoId: String) : MemoUpdateResult
    data class Forbidden(val reason: String) : MemoUpdateResult
    data class Rejected(val reason: String) : MemoUpdateResult
}
```

- `NotFound`：记忆不存在。
- `Forbidden`：记忆属于另一个 `appId`。
- `Rejected`：新正文无效。
- `Success.degraded`：更新已完成，但结构化过程使用降级逻辑。

## 9. 删除记忆：`memoDelete`

```kotlin
suspend fun memoDelete(
    memoId: String
): MemoDeleteResult
```

当前删除只作用于 Local Tree，并写入 `COLLECT/delete` 审计记录。它**不会保证同步删除已经存在于 Cloud Tree 的镜像**。

```kotlin
sealed interface MemoDeleteResult {
    data object Success : MemoDeleteResult
    data class NotFound(val memoId: String) : MemoDeleteResult
    data class Forbidden(val reason: String) : MemoDeleteResult
}
```

调用方可以根据业务语义把 `NotFound` 作为幂等删除处理，但 `Forbidden` 应明确提示权限 / 所有权问题。

## 10. 检索记忆：`getMemo`

```kotlin
suspend fun getMemo(
    query: String,
    limit: Int = 10,
    semantic: Boolean = true
): List<MemoryMemo>
```

| 参数 | 说明 |
|---|---|
| `query` | 自然语言检索词；空白查询返回空列表 |
| `limit` | 默认 10，系统收敛到 1～20 |
| `semantic` | 是否对关键词候选执行模型语义重排，默认 `true` |

当前流程是：

```text
权限过滤
→ 关键词切分与召回
→ semantic=true 时对候选执行模型语义重排
→ 更新命中统计
→ 写 RETRIEVE 日志
```

中文长查询会生成二字滑窗关键词。语义重排只对候选进行排序，并不是在无候选时自动执行向量全库搜索。

所有普通业务应用的读取上限固定为 `policyLevel <= 1`，调用方不能自行传入更高的 `policyMax`。接口只读取 Local Tree。

```kotlin
val memories = memoryClient.getMemo(
    query = "我周末准备学习什么？",
    limit = 5,
    semantic = true
)

val contextText = memories.joinToString("
") { memory ->
    "- [${memory.memoId}] ${memory.title}: ${memory.content}"
}
```

当语义模型失败时，系统保留关键词候选顺序并在审计日志中记录原因，接口仍然返回可用结果。

## 11. 获取场景上下文：`autoRecommend`

```kotlin
suspend fun autoRecommend(
    scene: String,
    limit: Int = 60
): List<MemoryMemo>
```

当前实现返回 Local Tree 中按 `updatedAt` 从新到旧排列的普通、未过期记忆。

- `scene` 是对用途的简短描述，主要用于审计和下游上下文说明；当前不会在 API 内部执行语义筛选。
- `limit` 默认 60，系统收敛到 1～100。
- 接口写 `RETRIEVE/auto_recommend` 日志。
- 不读取 Cloud Tree，也不会扫描设备文件。
- `WRITE` 应用调用会抛 `MemoryApiAccessException`。

文件分类管理器的现有使用方式：

```kotlin
val memories = memoryClient.autoRecommend(
    scene = "根据记忆标题、标签和正文摘要生成开放文件类别",
    limit = 60
)

val modelInput = memories.joinToString("
") { memory ->
    "标题=${memory.title}; 标签=${memory.tags.joinToString()}; " +
        "摘要=${memory.content.take(80)}"
}
```

## 12. 记录业务推理：`recordInference`

如果业务应用自行调用模型，可以通过统一接口留下 `INFER` 审计记录：

```kotlin
memoryClient.recordInference(
    action = "chat_answer",
    summary = "回答用户的 Android 学习计划问题",
    memoIds = memories.map(MemoryMemo::memoId),
    succeeded = true,
    reason = ""
)
```

当前字段处理规则：

- `action` 最多保留 40 个字符；
- `summary` 按 120 个字符阈值截断；
- `reason` 按 300 个字符阈值截断；
- `memoIds` 以逗号连接后写入日志；
- 该方法只写审计记录，不自动发起模型调用。

## 13. 推荐的接入流程

一个新的逻辑应用至少需要明确以下内容：

| 设计项 | 示例 | 为什么需要 |
|---|---|---|
| 稳定应用 ID | `app_calendar` | 用于记忆所有权和审计身份 |
| 展示名称 | `日程助手` | 用于应用登记和用户可见日志 |
| 稳定 `source` | `calendar` | 用于来源追踪与 24 小时同源去重 |
| 最小 scope | `WRITE` | 只写入时不要申请读取能力 |
| 写入内容 | `周五 15:00 做项目汇报` | `memoCollect` 的自然语言输入 |
| 业务对象 → `memoId` 映射 | `event-42 → MEMO-...` | 支持后续更新和删除 |
| 用户授权状态 | 已允许关联记忆 | 用户拒绝后不应继续写入 |

推荐接入顺序：

1. 先确定业务只写还是读写，选择最小 scope。
2. 在 `Phase3App` 中增加经过审核的固定身份。
3. 使用 `MemoryApiService.client(applicationContext, app)` 创建客户端。
4. 在用户明确同意后，把单条可独立理解的文本交给 `memoCollect`。
5. 保存成功后持久化 `memoId` 映射。
6. 业务对象变化时调用 `memoUpdate`；删除时明确让用户决定是否同步删除记忆。
7. 读取型应用处理 `MemoryApiAccessException`、空结果与模型重排降级。
8. 业务自己的模型推理使用 `recordInference` 留痕。
9. 使用结构化并发，避免 Activity / Fragment 销毁后继续回调旧 UI。

### 生命周期安全的调用骨架

```kotlin
class ExampleActivity : AppCompatActivity() {
    private val memoryClient by lazy {
        MemoryApiService.client(applicationContext, Phase3App.CHAT)
    }

    private fun associateMemory(content: String) {
        lifecycleScope.launch {
            try {
                when (val result = memoryClient.memoCollect(content)) {
                    is MemoCollectResult.Success -> {
                        persistMemoId(result.memory.memoId)
                    }
                    is MemoCollectResult.Duplicate -> {
                        persistMemoId(result.memory.memoId)
                    }
                    is MemoCollectResult.Rejected -> {
                        showError(result.reason)
                    }
                }
            } catch (error: MemoryApiAccessException) {
                showError("当前应用没有所需的记忆权限")
            } catch (error: Exception) {
                showError(error.message ?: "记忆服务暂时不可用")
            }
        }
    }
}
```

## 14. 仓库中的三个接入示例

| 应用 | scope | 使用接口 | 关键接入方式 |
|---|---|---|---|
| 备忘录 | `WRITE` | `memoCollect`、`memoUpdate`、`memoDelete` | 用户决定是否把笔记与记忆关联，并持久化 `memoId` |
| ChatBot | `READ_WRITE` | `getMemo`、`memoCollect`、`recordInference` | 把普通记忆注入问答上下文，再把提炼出的项目 / 会话记忆写回系统 |
| 文件分类管理器 | `READ_WRITE` | `autoRecommend`、`recordInference` | 不读真实文件；根据 Local Tree 普通记忆生成开放类别 |

这些应用是当前 API 最直接的参考实现。需要特别注意：它们仍与 OS Memory 运行在同一个 APK / 进程中。

## 15. 错误与降级约定

| 场景 | 当前行为 |
|---|---|
| collect / update 内容为空 | 返回 `Rejected("内容为空")` |
| collect / update 超过 5000 字符 | 返回 `Rejected` |
| 24 小时同源重复写入 | `memoCollect` 返回 `Duplicate` |
| 更新 / 删除不存在的 ID | 返回 `NotFound` |
| 更新 / 删除其他应用的记忆 | 返回 `Forbidden` |
| `WRITE` 应用读取 | 抛 `MemoryApiAccessException` |
| 空白检索词 | 返回空列表 |
| `limit` 超范围 | 自动收敛到接口上限 |
| 云端模型失败 | 写入 / 更新使用降级结构；检索保留关键词顺序并留痕 |
| 离线且端侧模型已准备 | 走 llama.cpp，不发云端 HTTP |
| 离线但模型缺失、损坏或 ABI 不支持 | 不尝试云端；写入 / 更新显式降级并记录原因 |
| Room / 磁盘等未预期故障 | 可能抛异常，调用方需要通用 `catch` |

`degraded=true` 表示“记忆已经保存，但 AI 结构化没有成功完成”，并不等同于写入失败。

## 16. 数据、模型与安全边界

### 数据边界

- `MemoryApiClient` 的 CRUD、`getMemo`、`autoRecommend` 都只访问 Local Tree。
- Cloud Tree 是独立 Room 数据库，用于模拟联网 / 内网隔离场景。
- Local Tree 中允许迁移且非敏感的记忆，可以由控制台网关单向同步到 Cloud Tree。
- Cloud Tree 内容不会通过 `MemoryApiClient` 返回，也不会在断网时同步回 Local Tree。
- `memoDelete` 只删除 Local Tree，不保证删除 Cloud Tree 中已有镜像。

### 模型边界

- 在线：统一路由到 OpenAI Chat Completions 兼容云模型。
- 离线：统一路由到本机 llama.cpp + Qwen GGUF，不回退云端 HTTP。
- 当前正式验证的端侧范围是控制台离线新增 Local Tree 记忆流水线。
- 当前 native runtime 只支持 `x86_64` 模拟器。

### 安全边界

- 普通业务应用最高只能读取 `policyLevel=1`。
- 敏感等级由确定性安全规则与模型判断共同决定，业务应用不能自行降级。
- 敏感记忆不对普通应用返回，也不允许同步到 Cloud Tree。
- 当前身份约束仍是同进程软件约束，不等于 Binder 场景下基于调用 UID 的系统级校验。

## 17. 当前没有的接口

为了避免把 Roadmap 当成现状，当前版本明确没有：

- 独立第三方 APK 的动态注册、授权和撤销协议；
- Binder/AIDL、SDK AAR 或 Maven Artifact；
- REST endpoint、网络鉴权 token 或 Webhook；
- Cloud Tree 的第三方读取接口；
- 批量 collect / update / delete 事务接口；
- 按 `memoId` 直接公开查询单条记忆的方法；
- 调用方自定义 `policyMax` 或读取敏感记忆的接口；
- 文件上传、文件内容读取或目录扫描接口；
- 多用户、租户、设备间同步与冲突解决协议；
- 加密数据库、Android Keystore 密钥封装或生产级权限沙箱。

## 18. 后续跨进程化的接口演进方向

未来如果让真正独立的第三方 APK 接入，建议尽量保持现有记忆语义，同时把传输与身份层升级为系统级接口：

1. 使用调用 UID、签名证书和授权记录绑定真实应用身份，不接受客户端自报 `appId`。
2. 将 `MemoryMemo` 与各类结果映射为稳定、带版本号的 Parcelable DTO。

5. 大结果集使用分页或流式接口，避免 Binder 一次传递大量对象。
