# OS Memory 当前版本对外接口文档

本文面向希望把业务功能接入 OS Memory 的 Android 开发者，说明当前版本真正可调用的接口、调用方需要提供的数据、权限规则、返回结果和已知边界。

## 0. 一分钟速览

| 问什么 | 答什么 |
|---|---|
| OS Memory 对外提供什么？ | 同 APK、同进程的 Kotlin 门面 `MemoryApiClient`，共 7 个方法：`register`、`memoCollect`、`memoUpdate`、`memoDelete`、`getMemo`、`autoRecommend`、`recordInference` |
| 调用方需要提供什么？ | 固定的应用身份（`Phase3App` 枚举值，需经审查加入）、要写入或检索的自然语言文本、本地业务对象到 `memoId` 的映射、用户的关联授权 |
| 调用方**不需要**提供什么？ | `appId` / `source`（与身份固定绑定）、标题 / 分类 / 标签 / 敏感等级 / 时间戳（由系统流水线生成）、模型配置与 API Key（由 OS Memory 统一配置） |
| 谁不能读记忆？ | `WRITE` scope 应用（当前只有备忘录）；调用读取接口会抛 `MemoryApiAccessException` |
| 敏感记忆如何处理？ | 安全规则与模型判断取并集，`policyLevel=2`；普通应用读不到，也不会同步到 Cloud Tree |
| 数据存在哪里？ | `MemoryApiClient` 所有方法只访问 Local Tree；Cloud Tree 是独立的隔离演示库，普通应用读不到 |
| 目前还不是什么？ | 不是 Binder/AIDL、ContentProvider、REST/HTTP；独立 APK 不能直接调用 |

## 1. 先说明“对外”的范围

当前接口是 **同 APK、同进程的 Kotlin API**：

```text
业务 Activity / Fragment
        ↓
MemoryApiService.client(context, Phase3App)
        ↓
MemoryApiClient
        ↓
MemoryRepository / Room / ModelProvider
```

它目前不是以下任何一种接口：

- 不是 Binder/AIDL 系统服务。
- 不是可被其他已安装 APK 绑定的 exported Android Service。
- 不是 ContentProvider。
- 不是 HTTP/REST 或 WebSocket API。
- 不是一组可以从其他进程直接调用的 JSON 接口。

因此，现阶段接入方必须与 OS Memory 一起编译进 `com.example.osmemory` 这个 APK。文档中的 DTO 和调用语义可以作为未来 Binder/AIDL 层的基础，但不能把本文示例复制到另一个独立 APK 后直接调用。

## 2. 当前提供的能力

推荐入口位于：

```kotlin
package com.example.osmemory.phase3.api
```

当前 `MemoryApiClient` 提供：

```kotlin
suspend fun register()

suspend fun memoCollect(
    content: String
): MemoCollectResult

suspend fun memoUpdate(
    memoId: String,
    content: String,
    forceSecret: Boolean? = null
): MemoUpdateResult

suspend fun memoDelete(
    memoId: String
): MemoDeleteResult

suspend fun getMemo(
    query: String,
    limit: Int = 10,
    semantic: Boolean = true
): List<MemoryMemo>

suspend fun autoRecommend(
    scene: String,
    limit: Int = 60
): List<MemoryMemo>

suspend fun recordInference(
    action: String,
    summary: String,
    memoIds: List<String> = emptyList(),
    succeeded: Boolean = true,
    reason: String = ""
)
```

业务应用通常只需要前六个记忆接口。`recordInference` 是辅助审计接口，用于记录业务应用自身发起的模型推理。

## 3. 获取客户端与应用身份

### 3.1 获取入口

```kotlin
import com.example.osmemory.phase3.api.MemoryApiService
import com.example.osmemory.phase3.api.Phase3App

val memoryClient = MemoryApiService.client(
    context = applicationContext,
    app = Phase3App.CHAT
)
```

`MemoryApiService` 会使用 `applicationContext`，因此客户端不会持有 Activity。每个接口都是 `suspend` 函数，应从生命周期受控的协程中调用。

### 3.2 当前固定应用身份

调用方不能在每次请求中随意填写 `appId` 或 `source`。二者由 `Phase3App` 固定绑定，以减少 UI 伪造调用方身份的机会。

| `Phase3App` | 启动器名称 | 固定 `appId` | 固定 `source` | `scope` |
|---|---|---|---|---|
| `NOTES` | 备忘录 | `app_notes` | `notes` | `WRITE` |
| `CHAT` | ChatBot | `app_chat` | `chat` | `READ_WRITE` |
| `CLASSIFIER` | 文件分类管理器 | `app_files` | `files` | `READ_WRITE` |

当前枚举只包含这三个身份。要把第四个逻辑应用接入当前单 APK，需要先在 `MemoryApiContract.kt` 中增加一个经过审查的 `Phase3App` 枚举值，再重新编译整个 APK；当前没有“运行时让任意第三方注册任意 appId”的公开接口。

### 3.3 Scope 权限

```kotlin
enum class MemoryScope {
    WRITE,
    READ_WRITE
}
```

| 能力 | `WRITE` | `READ_WRITE` |
|---|---:|---:|
| `register` | 允许 | 允许 |
| `memoCollect` | 允许 | 允许 |
| 修改自己创建的记忆 | 允许 | 允许 |
| 删除自己创建的记忆 | 允许 | 允许 |
| `getMemo` | 不允许 | 允许 |
| `autoRecommend` | 不允许 | 允许 |
| `recordInference` | 允许 | 允许 |

`WRITE` 调用读取接口会抛出 `MemoryApiAccessException`。无论 scope 是什么，`memoUpdate` 和 `memoDelete` 都只允许处理 `MemoryMemo.appId` 等于当前调用方 `appId` 的记忆。

### 3.4 注册行为

```kotlin
memoryClient.register()
```

- 注册把固定的 `appId`、显示名和 scope 幂等写入 `registered_apps`。
- 重复注册不会创建多份应用记录。
- 调用其他 API 前不必手工注册；客户端会在第一次调用时自动完成注册。
- `register()` 没有返回值。数据库或其他未预期的基础设施错误仍可能作为异常抛出。

## 4. 通用返回 DTO：MemoryMemo

所有成功写入、重复命中和读取结果都使用与 Room 实体解耦的 DTO：

```kotlin
data class MemoryMemo(
    val memoId: String,
    val content: String,
    val title: String,
    val category: String,
    val tags: List<String>,
    val source: String,
    val appId: String,
    val policyLevel: Int,
    val createdAt: Long,
    val updatedAt: Long,
    val confidence: Float
)
```

字段说明：

| 字段 | 类型 | 含义 |
|---|---|---|
| `memoId` | `String` | 系统生成的稳定记忆 ID；更新和删除必须使用它 |
| `content` | `String` | 净化后的原始正文，目前主要是去除首尾空白 |
| `title` | `String` | 模型抽取或降级生成的短标题 |
| `category` | `String` | 模型抽取或降级生成的记忆类别 |
| `tags` | `List<String>` | 结构化标签列表 |
| `source` | `String` | 调用应用身份绑定的来源，例如 `notes` |
| `appId` | `String` | 创建该记忆的应用 ID，用于所有权判断 |
| `policyLevel` | `Int` | `1` 表示普通记忆，`2` 表示敏感记忆 |
| `createdAt` | `Long` | 创建时间，Unix epoch milliseconds |
| `updatedAt` | `Long` | 最近更新时间，Unix epoch milliseconds |
| `confidence` | `Float` | 结构化抽取置信度；模型失败降级时会使用降级值 |

这是 Kotlin 对象，不是当前传输层上的 JSON。下面的 JSON 只用于帮助理解字段：

```json
{
  "memoId": "MEMO-1786000000000-123456",
  "content": "我计划周六上午复习 Android JNI",
  "title": "周六复习 Android JNI",
  "category": "任务轨迹",
  "tags": ["Android", "JNI", "复习"],
  "source": "chat",
  "appId": "app_chat",
  "policyLevel": 1,
  "createdAt": 1786000000000,
  "updatedAt": 1786000000000,
  "confidence": 0.88
}
```

## 5. 写入记忆：memoCollect

### 签名

```kotlin
suspend fun memoCollect(content: String): MemoCollectResult
```

### 调用方需要提供

| 数据 | 是否必需 | 规则 |
|---|---:|---|
| `content` | 是 | 自然语言文本；trim 后不能为空，最多 5000 个字符 |

调用方不提供 `appId`、`source`、标题、分类、标签、敏感等级、时间或置信度。这些身份字段由客户端固定，结构化字段由系统流水线产生。

推荐每次提交一条相对独立、能单独理解的事实、偏好、计划或事件。例如：

```kotlin
val result = memoryClient.memoCollect(
    "我计划周六上午复习 Android JNI，并整理端侧模型部署笔记。"
)
```

### 处理流程

```text
trim / 长度校验
→ 确定性安全规则
→ 在线云模型或离线端侧模型结构化抽取
→ 安全规则与模型敏感判断取并集
→ 24 小时同 source、同归一化正文去重
→ Local Tree 入库
→ 写入 COLLECT / INFER，敏感时另写 SECURITY 日志
```

普通记忆默认允许后续同步，敏感记忆默认保密隔离。模型失败时，流水线会用原文生成降级结构并继续入库，同时在结果和日志中明确标记，不会静默丢失输入。

### 返回结果

```kotlin
sealed interface MemoCollectResult {
    data class Success(
        val memory: MemoryMemo,
        val degraded: Boolean
    ) : MemoCollectResult

    data class Duplicate(
        val memory: MemoryMemo
    ) : MemoCollectResult

    data class Rejected(
        val reason: String
    ) : MemoCollectResult
}
```

- `Success`：创建成功。`degraded=true` 表示模型不可用或解析失败后使用了降级结构。
- `Duplicate`：24 小时内找到同 `source`、同归一化正文的已有记忆，返回已有对象，不再创建新记录。
- `Rejected`：输入为空或超过 5000 个字符；`reason` 是可展示给用户的中文原因。

### 完整处理示例

```kotlin
when (val result = memoryClient.memoCollect(userText)) {
    is MemoCollectResult.Success -> {
        saveMapping(localRecordId, result.memory.memoId)
        showMessage(if (result.degraded) "已降级保存" else "已写入记忆")
    }

    is MemoCollectResult.Duplicate -> {
        // 避免多个业务对象共享同一 memoId 后发生误删；先复用或合并本地对象。
        showExistingMemory(result.memory.memoId)
    }

    is MemoCollectResult.Rejected -> {
        showMessage("未保存：${result.reason}")
    }
}
```

## 6. 修改记忆：memoUpdate

### 签名

```kotlin
suspend fun memoUpdate(
    memoId: String,
    content: String,
    forceSecret: Boolean? = null
): MemoUpdateResult
```

### 调用方需要提供

| 数据 | 是否必需 | 规则 |
|---|---:|---|
| `memoId` | 是 | 必须是此前保存的系统记忆 ID |
| `content` | 是 | 新正文；trim 后不能为空，最多 5000 个字符 |
| `forceSecret` | 否 | `true` 强制不进入云同步；`false` 对非敏感内容允许同步；`null` 沿用原同步偏好 |

`forceSecret` 控制的是是否允许同步到 Cloud Tree，不是让调用方自行降低敏感等级。只要安全规则或模型判断为敏感，系统都会强制 `policyLevel=2` 并禁止同步。

更新会保留 `memoId` 和 `createdAt`，重新运行安全门控与结构化抽取，刷新 `updatedAt`，并写入审计日志。

### 返回结果

```kotlin
sealed interface MemoUpdateResult {
    data class Success(
        val memory: MemoryMemo,
        val degraded: Boolean
    ) : MemoUpdateResult

    data class NotFound(val memoId: String) : MemoUpdateResult
    data class Forbidden(val reason: String) : MemoUpdateResult
    data class Rejected(val reason: String) : MemoUpdateResult
}
```

- `NotFound`：对应记忆不存在。
- `Forbidden`：记忆属于另一个 `appId`。
- `Rejected`：新正文为空或超过 5000 个字符。
- `Success.degraded` 与 `memoCollect` 的含义相同。

示例：

```kotlin
when (
    val result = memoryClient.memoUpdate(
        memoId = linkedMemoId,
        content = editedText,
        forceSecret = true
    )
) {
    is MemoUpdateResult.Success -> render(result.memory)
    is MemoUpdateResult.NotFound -> removeBrokenMapping(result.memoId)
    is MemoUpdateResult.Forbidden -> showMessage(result.reason)
    is MemoUpdateResult.Rejected -> showMessage(result.reason)
}
```

## 7. 删除记忆：memoDelete

### 签名

```kotlin
suspend fun memoDelete(memoId: String): MemoDeleteResult
```

### 调用方需要提供

调用方只需提供此前保存的 `memoId`。删除仅作用于 Local Tree，并写入一条 `COLLECT/delete` 审计记录。当前不会同时删除 Cloud Tree 中可能已经存在的镜像。

### 返回结果

```kotlin
sealed interface MemoDeleteResult {
    data object Success : MemoDeleteResult
    data class NotFound(val memoId: String) : MemoDeleteResult
    data class Forbidden(val reason: String) : MemoDeleteResult
}
```

示例：

```kotlin
when (val result = memoryClient.memoDelete(linkedMemoId)) {
    MemoDeleteResult.Success -> removeLocalMapping()
    is MemoDeleteResult.NotFound -> removeLocalMapping() // 对调用方可按幂等删除处理
    is MemoDeleteResult.Forbidden -> showMessage(result.reason)
}
```

## 8. 检索记忆：getMemo

### 签名

```kotlin
suspend fun getMemo(
    query: String,
    limit: Int = 10,
    semantic: Boolean = true
): List<MemoryMemo>
```

### 调用方需要提供

| 数据 | 是否必需 | 规则 |
|---|---:|---|
| `query` | 是 | 自然语言检索词；空白查询直接返回空列表 |
| `limit` | 否 | 默认 10；系统自动限制在 1 到 20 |
| `semantic` | 否 | 默认 `true`；是否对关键词候选执行模型语义重排 |

流程为关键词切分与召回、权限过滤、可选语义重排、命中次数更新、`RETRIEVE` 日志。中文长查询会生成二字滑窗关键词；语义重排并不是无候选时的向量全库搜索。

所有普通应用的最高读取权限固定为 `policyLevel<=1`，调用方不能传入更高的 `policyMax`。敏感记忆不会返回。接口只读取 Local Tree，不读取 Cloud Tree。

当模型重排失败时，系统保留关键词候选顺序并在审计日志中记录降级原因；接口仍返回可用列表。

示例：

```kotlin
val memories = memoryClient.getMemo(
    query = "我周末准备学习什么？",
    limit = 5,
    semantic = true
)

val contextText = memories.joinToString("\n") { memory ->
    "- [${memory.memoId}] ${memory.title}: ${memory.content}"
}
```

`Phase3App.NOTES` 的 scope 是 `WRITE`，调用此方法会抛出 `MemoryApiAccessException`。

## 9. 场景上下文：autoRecommend

### 签名

```kotlin
suspend fun autoRecommend(
    scene: String,
    limit: Int = 60
): List<MemoryMemo>
```

### 调用方需要提供

| 数据 | 是否必需 | 规则 |
|---|---:|---|
| `scene` | 是 | 对当前用途的简短描述，主要用于审计和下游上下文说明 |
| `limit` | 否 | 默认 60；系统自动限制在 1 到 100 |

当前实现返回 Local Tree 中按 `updatedAt` 从新到旧排列的普通、未过期记忆。`scene` 本身目前不会在 API 内部执行语义筛选；业务应用应根据返回的标题、标签和正文摘要完成自己的场景编译或模型调用。

接口会写入 `RETRIEVE/auto_recommend` 日志，不读取 Cloud Tree，也不会扫描设备文件。`WRITE` 应用调用时会抛出 `MemoryApiAccessException`。

文件分类管理器的用法示例：

```kotlin
val memories = memoryClient.autoRecommend(
    scene = "根据记忆标题、标签和正文摘要生成开放文件类别",
    limit = 60
)

val modelInput = memories.joinToString("\n") { memory ->
    "标题=${memory.title}; 标签=${memory.tags.joinToString()}; " +
        "摘要=${memory.content.take(80)}"
}
```

## 10. 记录业务推理：recordInference

业务应用自行调用模型后，可以留下统一审计记录：

```kotlin
memoryClient.recordInference(
    action = "chat_answer",
    summary = "回答用户的 Android 学习计划问题",
    memoIds = memories.map(MemoryMemo::memoId),
    succeeded = true,
    reason = ""
)
```

字段处理规则：

- `action` 最多保留 40 个字符。
- `summary` 按 120 个字符阈值截断，超长时追加省略号。
- `reason` 按 300 个字符阈值截断，超长时追加省略号。
- `memoIds` 会以逗号连接后写入日志。
- 该接口只写 `INFER` 审计记录，不自动发起模型调用。

## 11. 推荐的应用接入流程

### 11.1 应用需要提供的数据

一个新的逻辑应用至少需要在设计阶段提供：

| 数据 | 示例 | 用途 |
|---|---|---|
| 稳定应用 ID | `app_calendar` | 记忆所有权和审计身份；发布后不要随意改变 |
| 展示名称 | `日程助手` | 应用登记和用户可见日志 |
| 稳定来源 | `calendar` | 24 小时同源去重和来源追踪 |
| 最小 scope | `WRITE` | 只写就不要申请读取权限 |
| 要写入的自然语言 | `周五 15:00 做项目汇报` | `memoCollect` 输入 |
| 本地记录与 `memoId` 的映射 | `event-42 → MEMO-...` | 后续修改、删除关联记忆 |
| 用户授权状态 | 已同意关联记忆 | 不应在用户拒绝后偷偷写入 |

API Key、云端 Model ID 和端侧模型路径由 OS Memory 统一配置，普通业务应用不应各自保存一套模型密钥。

### 11.2 接入步骤

1. 评估业务只需要写入还是需要读写，遵循最小权限原则选择 scope。
2. 在 `Phase3App` 中增加经过审核的固定身份；不要把 `appId` 暴露为任意用户输入。
3. 使用 `MemoryApiService.client(applicationContext, app)` 创建客户端。
4. 在用户明确同意后，把单条、可独立理解的文本传给 `memoCollect`。
5. 保存成功或重复结果中的 `memoId`，建立业务对象到记忆对象的映射。
6. 业务对象变化时调用 `memoUpdate`；删除时让用户选择是否同步删除记忆。
7. 读取型应用处理 `MemoryApiAccessException`、空结果和语义重排降级。
8. 对模型推理调用 `recordInference` 留下可解释的审计记录。
9. 在应用销毁时依赖结构化并发取消协程，避免过期 UI 接收结果。

### 11.3 一个生命周期安全的调用骨架

```kotlin
class ExampleActivity : AppCompatActivity() {
    private val memoryClient by lazy {
        MemoryApiService.client(applicationContext, Phase3App.CHAT)
    }

    private fun associateMemory(content: String) {
        lifecycleScope.launch {
            try {
                when (val result = memoryClient.memoCollect(content)) {
                    is MemoCollectResult.Success -> {
                        persistMemoId(result.memory.memoId)
                    }
                    is MemoCollectResult.Duplicate -> {
                        persistMemoId(result.memory.memoId)
                    }
                    is MemoCollectResult.Rejected -> {
                        showError(result.reason)
                    }
                }
            } catch (error: MemoryApiAccessException) {
                showError("当前应用没有所需的记忆权限")
            } catch (error: Exception) {
                showError(error.message ?: "记忆服务暂时不可用")
            }
        }
    }
}
```

### 11.4 三个现有应用的接入速览

仓库内的三个应用就是这套 API 的现成范例，接入方式可直接参照：

| 应用 | 身份 / scope | 用到的接口 | 调用方自己管理的数据 | 关键点 |
|---|---|---|---|---|
| 备忘录 | `NOTES` / `WRITE` | `memoCollect`、`memoUpdate`、`memoDelete` | 笔记正文、本地笔记记录到 `memoId` 的映射 | 遇到 `Duplicate` 拒绝关联，避免多条笔记共享同一记忆后误删 |
| ChatBot | `CHAT` / `READ_WRITE` | `getMemo`、`memoCollect`、`recordInference` | 项目名、会话 ID、逐轮提炼的会话记忆本地副本 | 启用 OS Memory 后把普通记忆作为上下文，并把模型生成的“项目X的会话记忆：…”写回系统 |
| 文件分类管理器 | `CLASSIFIER` / `READ_WRITE` | `autoRecommend`、`recordInference` | 已生成的开放类别（本地 SharedPreferences） | 不读真实文件；读取本地普通记忆 → 请求模型生成开放类别 → 清洗后追加到“家庭/工作/生活/旅行”之外 |

## 12. 错误和降级约定

| 场景 | 当前行为 |
|---|---|
| collect/update 内容为空 | 返回 `Rejected("内容为空")` |
| collect/update 超过 5000 字符 | 返回 `Rejected` |
| 24 小时同源重复写入 | collect 返回 `Duplicate` |
| 更新/删除不存在的 ID | 返回 `NotFound` |
| 更新/删除其他应用的记忆 | 返回 `Forbidden` |
| `WRITE` 应用读取 | 抛出 `MemoryApiAccessException` |
| 空白检索词 | 返回空列表 |
| limit 超出范围 | 自动收敛到接口上限，不抛错 |
| 云端模型失败 | 收集/更新使用降级结构入库；检索保留关键词顺序，并留日志 |
| 离线且端侧模型已准备 | 模型调用走 llama.cpp，不发云端 HTTP |
| 离线但模型缺失、损坏或 ABI 不支持 | 不尝试云端；收集/更新显式降级入库并记录原因 |
| Room/磁盘等未预期故障 | 可能抛出异常，调用方需要通用 `catch` |

`degraded=true` 不等于写入失败。它表示记忆已经保存，但标题、分类或标签来自确定性降级逻辑，而不是一次成功的模型抽取。

## 13. Local Tree、Cloud Tree 与模型路由边界

需要把“数据保存在哪里”和“使用哪个模型处理”分开理解：

### 数据边界

- `MemoryApiClient` 的 CRUD、`getMemo`、`autoRecommend` 都只访问 Local Tree。
- Cloud Tree 是独立 Room 数据库，用于模拟联网/内网状态下的云树。
- Local Tree 中允许迁移且非敏感的记忆，可以由控制台网关单向同步到 Cloud Tree。
- Cloud Tree 内容不会通过 `MemoryApiClient` 返回，也不会在断网时同步回 Local Tree。
- `memoDelete` 只删除 Local Tree，不保证删除已经存在的 Cloud Tree 镜像。

### 模型边界

- 在线：统一 `ModelProvider` 路由到 OpenAI 兼容云端模型。
- 离线：统一路由到本机 llama.cpp + Qwen GGUF，绝不回退云端 HTTP。
- 当前正式验证的端侧范围是控制台离线新增本地记忆流水线。
- 端侧模型必须提前在模型设置页下载并校验，且当前 native runtime 仅支持 `x86_64` 模拟器。

### 安全边界

- 普通应用读取上限固定为 `policyLevel=1`。
- 敏感内容由确定性安全规则与模型敏感判断取并集，不能由调用应用主动降级。
- 敏感记忆不会通过普通应用读取，也不允许迁移到 Cloud Tree。
- 当前身份约束是同进程软件约束，不等同于 Android Binder 调用 UID 校验。

## 14. 当前不提供的接口

为避免接入方误判，当前版本没有：

- 独立 APK 的注册、授权和撤销协议。
- Binder/AIDL、SDK AAR 或 Maven Artifact。
- REST endpoint、网络鉴权 token 或 Webhook。
- Cloud Tree 的第三方读取接口。
- 批量 collect/update/delete 事务接口。
- 按 memoId 直接查询单条记忆的公开方法。
- 调用方自定义 `policyMax` 或读取敏感记忆的接口。
- 文件上传、文件内容读取、目录扫描接口。
- 多用户、租户、设备间同步与冲突解决协议。
- 加密数据库、Android Keystore 密钥封装或生产级权限沙箱。

## 15. 后续跨进程化建议

未来若要让独立第三方 APK 接入，建议保持本文方法语义，但在 Binder/AIDL 层补齐：

1. 使用调用 UID、签名证书和授权记录绑定真实应用身份，不接受客户端自报 appId。
2. 将 `MemoryMemo` 和密封结果映射为稳定、带版本号的 Parcelable DTO。
3. 使用显式错误码区分 rejected、not found、forbidden、degraded 和内部错误。
4. 对读取权限增加用户可见授权、撤销和敏感数据确认流程。
5. 对大列表使用分页或流式接口，而不是 Binder 中一次返回大量对象。
6. 为 API 增加版本协商、兼容性测试、速率限制和完整审计。

这些是演进建议，不代表当前仓库已经实现。
